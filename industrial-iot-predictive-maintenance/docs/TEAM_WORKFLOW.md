# Three-person GitHub workflow

Repository: `https://github.com/Nirlepb/industrial-iot-predictive-maintenance`

## Responsibility split

### Person 1 — Sensor simulation and database
Branch: `feature/sensor-database`

- Own `sensor_simulator.py`.
- Document InfluxDB 3 Core setup and the `industrial_iot` database / `machine_telemetry` measurement contract.
- Coordinate field names and tags with Persons 2 and 3.
- Avoid changing report/dashboard files unless agreed with the team.

### Person 2 — Analytics and maintenance reports
Branch: `feature/analytics`

- Own `anomaly_analytics.py`, `trend_analysis.py`, and `maintenance_monitor.py`.
- Keep SQL field names consistent with the simulator's measurement.
- Test reports against data generated by Person 1's simulator.

### Person 3 — Dashboard and integration
Branch: `feature/dashboard`

- Own `dashboard.py`, `requirements.txt`, `.gitignore`, `README.md`, and integration documentation.
- Test the dashboard against the same InfluxDB database and schema.
- Coordinate merges and run the final end-to-end check.

## Repository owner: initial setup

Create an empty repository on GitHub named `industrial-iot-predictive-maintenance` under account `Nirlepb`. Do not initialize it with a README, `.gitignore`, or license if you will push this prepared folder as the first commit.

In a terminal opened in this project folder:

```bash
git init
git branch -M main
git add .
git commit -m "Initial commit: Industrial IoT project"
git remote add origin https://github.com/Nirlepb/industrial-iot-predictive-maintenance.git
git push -u origin main
```

If the remote repository already contains commits, stop and inspect the remote before pushing; do not force-push blindly.

Invite the other two GitHub accounts through **Repository Settings → Collaborators**. Each invited collaborator must accept the invitation.

## Each team member: first-time setup

Run these commands once, replacing `BRANCH_NAME` with the assigned branch:

```bash
git clone https://github.com/Nirlepb/industrial-iot-predictive-maintenance.git
cd industrial-iot-predictive-maintenance
git switch -c BRANCH_NAME
```

Use exactly one of these branch names:

```text
feature/sensor-database
feature/analytics
feature/dashboard
```

## Each work session

Before starting work:

```bash
git switch YOUR_BRANCH_NAME
git pull origin main
```

Make changes only to files in your assigned area. Then:

```bash
git status
git add path/to/your-file.py
git commit -m "Describe the change"
git push -u origin YOUR_BRANCH_NAME
```

For later pushes to the same branch, `git push` is enough.

Open a pull request on GitHub from your feature branch into `main`. Describe the change and how it was tested. Ask another teammate to review it. Resolve conflicts and test before merging.

## Integration order

1. Person 1 confirms the database endpoint, database name, measurement, tags, and field names.
2. Person 2 tests analytics and report scripts against simulator data.
3. Person 3 integrates the dashboard and documentation.
4. All members run the end-to-end smoke test and review the final README.

## Avoiding conflicts

- Agree on shared SQL fields and threshold rules before changing them.
- Avoid having two people edit the same file at the same time.
- Pull `main` before starting new work and before opening a pull request.
- Do not commit virtual environments, credentials, local database files, or generated cache files.
- Never use `git push --force` on shared branches unless the team explicitly agrees and understands the impact.

## Final smoke test

With InfluxDB 3 Core running and `industrial_iot` configured:

1. Start `python sensor_simulator.py`.
2. Confirm telemetry writes succeed.
3. Run each report script.
4. Start `streamlit run dashboard.py`.
5. Confirm the dashboard shows readings and charts.
6. Record any remaining issues in GitHub Issues before the final submission.
